# Dev

`camera-main` の改良版。ハード（配線・ピン・カメラ設定）は変えずにソフトだけ直している。VS Codeではこの `Dev` フォルダを開く。

スマホからWi-Fiとバックアップ先を設定できる。手順は [NETWORK_SETUP.md](NETWORK_SETUP.md)。内部の作りは [ARCHITECTURE.md](ARCHITECTURE.md)。

## camera-main から直したところ

- 保存名を「枚数+1」で決めていたので、写真を消すと番号がかぶっていた → `.jpg` / `.JPG` / `.tmp` で使っている番号を避けて空き番号を使う
- 保存失敗で壊れたJPEGが残る → いったん `.tmp` に書き、サイズと中身を読み戻して確認してから `.jpg` にリネーム
- エラー解除してもSDを再初期化しなかった → エラー中の最初の押下でSDとカメラを再初期化
- 初期化に失敗してもReady LEDが点いていた → 初期化と起動時の画像取得の結果を見る
- 待ち時間中に押しっぱなしにすると、待ち明けに撮影されていた → 一度離して押し直すまで撮らない
- チャタリング → 30ms安定で判定。長押しは1回
- `camera_config_t` に未初期化の値が残っていた → ゼロ初期化
- 空のフレームを保存しようとしていた → エラーにしてフレームを返却
- LEDの状態を毎ループログに出していた → 変化したときだけ
- 状態があちこちの変数に散らばっていた → `CaptureState` 1つにまとめた
- 露出待ちの `delay()` でループが止まっていた → 時間を見て進める形にした。待っている間もボタンを見る
- 起動時・準備中・保存中の押しっぱなしが次の撮影になることがあった → 押し始めたときに受付中だったかを覚えておく
- フレームの返却が分岐ごとにバラバラ → `ScopedFrame` でスコープを抜けたら返す

ピン、画質、500msの撮影間隔は元のまま。Webページは設定用だけで、旧コードの写真表示・LED操作ページは出していない。

## Wi-Fi とバックアップ

- スマホのブラウザからWi-Fiを選ぶ。3件まで保存、切れたら再接続
- 設定はNVSに保存するので、SSIDやパスワードをソースに書く必要はない
- バックアップ先はHTTPSのWebDAV（Basic認証）だけ。Google Driveなどは未対応
- 通信は撮影とは別タスク。写真はPSRAMにコピーしてから送るので、HTTP中はSDをロックしない（読み込みも16KBごとにロックを外す）
- 送ったあとGETで読み戻して一致したら、SDに送信済みの記録を残す。失敗や再起動後は未送信分をやり直す
- SDの写真は消さない。2MBを超える写真は自動送信しない

パーティションは `huge_app.csv`（アプリ3MB）にした。Wi-Fiを入れたら標準の領域で99%使っていたため。4MB以上のフラッシュが必要（ボード設定は16MB）。OTAはなし。

## 使い方

1. SDを入れて電源ON
2. GPIO46が点いたらGPIO47で撮影
3. 保存して500ms経つと次が撮れる
4. GPIO38（エラー）が点いたらカードなどを確認。保存中に抜かない
5. GPIO47を1回押すとSDとカメラを再初期化する（撮影はしない）
6. 直ったら、離してもう一回押すと撮れる

GPIO1は外のWi-Fiにつながっているときに点く。設定用APを出しているだけでは点かない。

GPIO46はソフトが確認できた状態を出しているだけで、待機中にカードが抜けても気づかない。

## 保存

SD直下に `1.jpg`, `2.jpg`, ...。空き番号を使うので、番号順＝撮影順とは限らない。

書き込み中は `1.tmp` などを使う。

- 書き込みや確認に失敗したら `.tmp` を消す
- リネームだけ失敗したら `.tmp` を残す
- 残っている `.tmp` は上書きも削除もせず、その番号を飛ばす。中身はPCで確認してから必要なら `.jpg` にする

読み戻しの確認は512バイトずつ元データと比べる。その分保存が遅くなるので、撮影間隔は実機で見ておく。

## ビルドとテスト

`camera` フォルダで実行する。

```powershell
pio run -d Dev
python Dev/test/run_host_tests.py --compiler <g++のパス>
python Dev/test/run_network_tests.py --compiler <g++のパス>
python Dev/test/test_setup_ui.py
```

`g++` がPATHにあれば `--compiler` はいらない。C++17が必要。

- ネットワークのテストはWindowsのSHA-256 APIを使うので Windows + MinGW 専用。先に `pio run -d Dev` か `pio pkg install -d Dev` で ArduinoJson 7.4.3 を入れておく
- 画面のテストは Playwright + Chromium（`pip install playwright` → `python -m playwright install chromium`）

テストは本物の `camera_control.cpp` などを、偽のカメラ・SD・時計と一緒にPC向けにビルドして動かす。

- 撮影・保存まわり 28ケース（欠番、再起動、`.tmp` の残り、書き込み失敗、読み戻し不一致、リネーム失敗、長押し、チャタリング、`millis()` の一周、SD復旧、カメラ失敗、LEDなど）
- ネットワーク・バックアップ 20ケース、接続管理と設定API 8ケース
- 設定画面 2ケース（PC幅とスマホ幅）

テスト用の偽ハードは `test/host/` にある。

## 確認状況（2026-09-26）

PCのテストとESP32-S3向けビルドは通った。実機への書き込み、実際のWi-Fi、WebDAVへの送信はまだ。

ビルド環境は PlatformIO Core 6.1.19 / Espressif 32 55.3.38（pioarduino）/ Arduino ESP32 3.3.8。`platformio.ini` でバージョンを固定していないので、別のPCだと変わるかもしれない。

実機で見ること:

- 何枚か撮ってPCで開けるか
- 1枚消してから撮って、他の写真が壊れないか
- 短押し・長押し・連打で余計な写真が増えないか
- ボタンを押したまま起動しても撮らないか
- SDなしで起動してエラーになり、カードを入れて復旧できるか
- 容量不足などでエラーになるか
- スマホで設定して、電源を入れ直しても残っているか
- バックアップ中に撮影しても両方開けるか
- Wi-FiやWebDAVを止めてもSDには撮れて、戻ったら送られるか

`platformio.ini` のポートは `COM11` のまま。旧Wi-Fi情報は `Dev` からは消した。
